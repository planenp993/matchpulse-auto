автоматично обновяване и независим одит. Следващата работа започва от реалния код.

## Архитектура

Статичен HTML/CSS/JavaScript сайт; Python със стандартната библиотека за импорт
и одит; JSON snapshots вместо SQL база. CommonJS тестове с Node.js.

Основни файлове:

- `scripts/update.py`: CSV резултати, seed импорт, запазване на допълнителни
  статистики при сливане, основна програма.
- `scripts/update_calendar.py` и `scripts/fixtures_fallback.py`: календарна
  актуализация, отделена от историческите CSV заявки.
- `scripts/backfill_openfootball.py` и `scripts/backfill_openfootball_txt.py`:
  OpenFootball архиви, произход на редовете и проверки на сезон/резултат.
- `scripts/refresh_openfootball.py`: седмични текущи резултати за D1 и I1.
- `scripts/audit_scout.py`: структурна проверка и покритие по лига, сезон и поле.
- `docs/scout-core.js`: история, профили на отбори, прозорци и разплащане.
- `docs/scout-elo.js`: Elo по първенство, домакински фактор, ограничено влияние
  на головата разлика, сезонно връщане към средното и предмачова хронология.
- `docs/scout-patterns.js`: 25 наблюдавани пазара и автоматично търсене на
  до три поддържани сигнала за една среща. Изисква налични реални наблюдения.
- `docs/model-core.js`: вероятностен голов модел; `docs/lab.html`: Match Lab.
- `scripts/build_scout_preview.py`: самостоятелен offline HTML snapshot.

Серии и исторически честоти не са калибрирани вероятности за следващия мач.
Elo все още е отделен по първенство; алиасите и преминаването между дивизии
остават задача за проверка. Показаните пазари за удари/корнери/картони все още
нямат данни, върху които да намират реални серии.

## Действаща автоматизация

Часовете по-долу са конфигурирани в **UTC**; GitHub може да стартира по-късно.

| Процес | График / тригер | Какво изпълнява |
|---|---|---|
| Основни исторически CSV | Вторник и петък, 05:17 UTC | `update.py --online`, включително календар |
| Сутрешен календар | Останалите дни, 05:17 UTC | `update_calendar.py` |
| Вечерен календар | Всеки ден, 17:17 UTC | `update_calendar.py` |
| Текущи OpenFootball резултати | Събота, 04:41 UTC | `refresh_openfootball.py` за D1/I1 и календар |
| Push към `main` | Промяна извън `docs/data/**` | Проверки и публикуване, без заявки за нови данни |
| Ръчно `update.yml` | `workflow_dispatch` | Календар, проверки и публикуване |
| V4 разработка | Определени промени в `scout-data-integrity-v4` | TXT backfill, тестове, browser проверка и запис само в този клон |
| `Scout Verify` | Pull request към `main`, push към `work/**`, ръчно | Всички Python/Node тестове, одит и smoke проверка; без заявки към спортни източници |

Основният workflow записва JSON обратно в `main` и публикува `docs` през GitHub
Pages. Изтегленият offline HTML не се обновява автоматично. Личните прогнози се
съхраняват в localStorage на устройството; автоматични Telegram публикации няма.

В тази работна промяна основният workflow вече изпълнява `tests/*.cjs`, включително
V4. Затворен е пропускът, при който до 50 структурни нарушения не спираха
публикуването: сега всяко отчетено нарушение е фатално. Липсата на допълнителни
статистики остава видимо предупреждение. Има регресионни тестове за двете поведения.

При възстановяването преминаха 28 Python и 42 Node теста. След корекцията
преминаха **30 Python и 42 Node теста — общо 72**. Добавените два теста проверяват,
че единичен дубликат спира процеса и че липсващите допълнителни статистики остават
предупредителни. Отделна проверка потвърди, че всичките 43 036 оригинални мача,
резултатите и наличните им допълнителни полета са запазени.

Преизчислената ретроспективна диагностика на головия модел включва 1 096 мача:
Brier 0,2404 срещу 0,2438 за лиговата база. Това е историческа диагностика на
съществуващата формула, без проверка на доходност или бъдещо представяне.

Командите за целия текущ пакет са:

```sh
python -m unittest discover -s tests -v
node --test tests/*.cjs
python scripts/audit_scout.py
node scripts/smoke_scout.cjs
```

Последният проверен V4 GitHub Actions run е
https://github.com/planenp993/matchpulse-auto/actions/runs/40228426123.
Той е успешен, включително Chromium проверки на телефон и десктоп, за тогавашния
V4 snapshot. Новата интеграция изисква собствен успешен `Scout Verify` run.
