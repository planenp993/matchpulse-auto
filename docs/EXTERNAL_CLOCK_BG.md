## Какво се изпълнява

Външната услуга само изпраща командата за стартиране. GitHub извършва
изтеглянето, проверките, архивирането и публикуването; не е нужен включен
личен компютър. Заявката извиква съществуващия `refresh-clock.yml` в режим
auto. При дължима работа той извиква същия `update.yml`.

Soccerway е основният календарен/скорошен резултатен източник с целеви
около 30 минути и съществуващия cooldown. Бавните исторически, официални UEFA,
таблицови и ценови източници запазват независимите си интервали. Ранна команда
може правилно да пропусне повторно изтегляне, ако има току-що успешна проверка.
Няма промяна на модели, скенер, дневникови конфигурации или стари прогнози.

Вътрешният GitHub cron остава допълващ; съществуващите source gates и различните
concurrency групи пазят от припокриване. Самите липсващи native събития не се
представят за поправени. Forebet и Statarea остават неактивни.

## Как се доказва повторението

1. За първата връзка е потвърден HTTP 200 и успешен GitHub test run 41118013045.
2. Провери истинско планирано изпълнение в cron-job.org HISTORY, не Test run.
3. Свери неговия отговор/run ID с новия GitHub workflow_dispatch.
4. Провери успешния Soccerway receipt:
   `last_soccerway_success_trigger.run_id` трябва да сочи съответния run.
5. Повтори за следващото планирано изпълнение. Зелен workflow сам по себе си
   не доказва успешен източник.

При външния часовник GitHub събитието е workflow_dispatch. Автоматичният
произход се доказва от планираната история на външната услуга. Ако тя е
недостъпна, отбележи ограничението и посочи само проверените публични факти.
